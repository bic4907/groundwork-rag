## 왜 차이가 났는가

### 1. BM25와 Hybrid: 연결 문서 누락

BM25의 test 근거 회수율은 Dense보다 16.67 pp 낮다. `Little Big League` 배우와
Kevin Costner 작품을 연결하는 질문에서는 마지막 연결 사실을 찾지 못해 보류했다.
Vector를 묻는 질문에서도 수학·질병의 vector 문서가 검색되어 음악 그룹과의 비교가
막혔다. 이런 사례에서는 이름 일치만으로 여러 문서를 연결하기 어렵다.

Hybrid도 모든 질문에서 개선되지 않았다. Ravi Khote의 음악이 쓰인 2003년 영화와
1966년의 다섯 번째 허리케인을 묻는 질문에서 연결 사실을 찾지 못해 보류했다.
검색 점수와 F1 변화가 동시에 있어도 전체 F1 차이를 검색 효과로만 단정할 수 없다.
동일 모델의 생성 표현 차이와 보류 판단도 영향을 준다.

### 2. Sufficiency: 보류의 이유를 구분해야 한다

test의 답변 가능 20문항 중 Dense는 모두 답했고 gate는 2문항을 보류했다.
두 사례의 성격은 다르다.

- `5ade3bf75542997c77adedb8`: 100권 이상 집필한 사람이 누구인지 묻는다. 문맥에는
  Chomsky가 100권 이상 집필했다는 직접 근거가 있지만, gate는 다른 후보 Yaşar Kemal의
  권수가 없다는 이유로 보류했다. 모든 비교 질문에 양쪽 속성이 필요하다는 지시가
  이 선택형 질문에서는 과도하게 적용된 사례다.
- `5adbe75455429944faac23af`: Joan Jett/Kenny Laguna의 음반 유통 회사 질문이다.
  Dense의 짧은 정답은 Gold와 일치해 F1=1이지만, 인용한 주장은 두 사람이 Blackheart
  Records를 설립했다는 사실이다. 유통 역할을 직접 인용하지 않았고 Gold 근거 회수율도
  50%다. gate는 유통 관계의 누락을 지적했다. F1 하락만으로 이 보류가 더 나쁜 근거 기반
  답변이라고 결론 내릴 수 없다. 의미적 충분성 라벨을 별도로 검토해야 한다.

따라서 이번 결과는 gate를 기본값으로 승격할 근거가 되지 않는다. 동시에 높은 lexical
F1 또는 인용 구절 존재만으로 답변의 모든 필수 관계가 뒷받침된다고 볼 수도 없다.

### 3. 오류와 전체 결과

전체 40문항에서 오류는 Dense 1건, BM25 2건, Hybrid/Sufficiency 0건이다. 오류는 모두
한 번의 수리 후에도 `invalid_answer_schema`인 경우이며 dev에 속한다. 실패한 원문 출력은
저장하지 않으므로 더 구체적인 JSON/필드 원인을 확정하지 않는다. 오류를 삭제하거나
정상 보류로 치환하지 않았다. 전체 F1은 Dense 57.81%, BM25 42.09%, Hybrid 47.62%,
Sufficiency 50.41%다.

## 비용과 지연: 전체 40문항씩

| 방식 | 답변 호출 | 충분성 호출 | 중앙 지연 | 추정 USD |
| --- | ---: | ---: | ---: | ---: |
| Dense | 42 | 0 | 2.79s | 0.2663 |
| BM25 | 42 | 0 | 3.12s | 0.2878 |
| Hybrid | 42 | 0 | 2.84s | 0.2746 |
| Dense + Sufficiency | 29 | 41 | 5.02s | 0.4193 |

호출 수에는 수리가 포함된다. gate가 답변 호출을 일부 생략해도 별도 판정 호출 때문에
Dense 대비 추정 비용은 약 **57%**, 중앙 지연은 약 **80%** 증가했다. 네 실행 합계는
약 **$1.2479**다. `.env`의 입력 $2/M·출력 $10/M 가격과 반환 usage를 적용한 추정치이며
실제 청구서 금액은 아니다. 임베딩·usage 미반환 요청 및 별도 GUI 실행은 제외한다.
Hybrid 실행 일부와 별도 GUI dev 실행이 겹쳤으므로 지연을 통제된 벤치마크로 보지 않는다.

## 다음 실험

1. 현재 관측된 Token F1·비용 기준의 기준선은 Dense로 유지한다.
2. 개발 데이터에서 '한 후보를 직접 식별하는 질문'과 '두 속성의 비교가 필요한 질문'을
   구분하도록 gate 지시를 수정하고, 새로운 평가 데이터를 먼저 고정한다.
3. 인용 구절의 존재뿐 아니라 질문의 필수 관계와 short answer까지 뒷받침하는지 독립
   Judge와 실제 사람 검토로 평가한다. 현재 보고서는 그 점수를 측정하지 않았다.
4. 같은 설정을 반복 실행해 표현 변동과 보류 변동을 분리한다. 이미 분석한 test의
   결과를 보고 튜닝한 뒤 같은 test로 일반화 개선을 주장하지 않는다.
